# HanPit — memoria agentica

## Intento e perimetro

App per imparare il cinese, destinazione futura Android. Web app con flashcard stile Anki, grammatica, letture progressive e test per livello. UI italiana minimale, niente testo decorativo o funzionalità aggiuntive. Preferire poco codice, dipendenze ridotte e costo computazionale basso.

Test implementati: sette blocchi HSK, 20 domande casuali per tentativo, 20 risultati perfetti consecutivi per sbloccare il successivo. Non reintrodurre il vecchio requisito 30 domande / 10 successi né il selettore libero: l’utente ha scelto lo sblocco obbligatorio. Vocabolario cumulativo, grammatica/letture del livello selezionato; lo sblocco non elimina progressi.

## Decisioni e invarianti

- Fonte di riferimento: GF0025-2021, 11.092 voci, livelli 1–6 e blocco avanzato comune 7–9. Non inventare una suddivisione di 7/8/9; non sostituire tacitamente i dati con programmi d’esame successivi.
- Nuove voci per blocco: 500, 772, 973, 1000, 1071, 1140, 5636. ID ufficiali `L1-0001` ecc. Identità distinta anche quando hanzi/pinyin coincidono; mai deduplicare per grafia.
- Flashcard con significati inglesi, chiaramente etichettati EN. Per i test, `word-italian-level-{1..7}.json` aggiunge 11.092 glosse brevi italiane editoriali derivate dalle stesse definizioni; non sono traduzioni ufficiali. Copertura esatta per ID, incluse omografie; licenza CC BY-SA 3.0 e provenienza in `public/data/README.md`.
- `src/study.ts`: FSRS-6 con `ts-fsrs` 5.4.2, ritenzione .9, passi 1m/10m e riapprendimento 10m, fuzz disabilitato. Primo Facile su una carta nuova: 5 giorni, tramite peso `w[3] = 5` (stabilità iniziale), non sovrascrivendo solo `due`. Nessuna riscrittura delle carte/scadenze già persistite. Ordine: apprendimento scaduto, ripasso scaduto, nuove; scansione O(n), senza sort/copie del mazzo per risposta. Nessun ripasso futuro anticipato.
- `src/storage.ts`: IndexedDB `hanpit` v1, store `cards`, `reviews`, `settings`; Date via structured clone. Carta/review atomiche prima della memoria/UI. `settings.testProgress` conserva `{unlockedLevel,streaks:Map<number,number>}`: lettura/modifica/scrittura nella stessa transazione, nessuno storico dei test. Memoria aggiornata dopo commit; errore azzera solo la serie corrente, mai gli sblocchi precedenti. Validare il livello anche nella persistenza.
- Reset esplicitamente richiesto dall’utente per questo aggiornamento: startup con `settings.progressRevision < 1` cancella atomicamente cards/reviews/settings e scrive `progressRevision=1`. Vale una sola volta per browser/origine, anche per browser utente diversi da quello di verifica; non cancellare nuovi progressi ai reload, non incrementare il marcatore senza nuova autorizzazione. Schema/ID invariati.
- `src/main.ts`: UI DOM nativa, selettore condiviso con opzioni bloccate oltre `unlockedLevel`; `src/vocabulary.ts` condivide cache Promise per livello e mazzo cumulativo fra flashcard/test. Vocabolario richiesto solo da Flashcard o Test, non da Grammatica/Letture. Timer solo per attesa senza carte; scorciatoie Spazio/1–4 solo flashcard; risposte asincrone obsolete ignorate. Nessun framework/backend/service worker.
- Audio: eliminata Web Speech API. `src/audio.ts` riproduce MP3 neurali locali `public/audio/{ID}.mp3`, generati da Kokoro-82M-v1.1-zh, voce mandarino zf_001 (Apache 2.0). Precaricare solo la carta corrente, mai parlare sul fronte; rivelazione e Ascolta avviano/ripetono. Stop su carta/livello/sezione/pagina nascosta; errori visibili, niente fallback robotico o API esterne. Unico elemento audio riusato, protezione dalle risposte asincrone obsolete.
- `scripts/generate-audio.py`: generazione offline CPU con modello/revisione/SHA-256 e dipendenze fissati; pinyin ufficiale prima dei fonemi, non lettura automatica dei polifonici dagli hanzi. Prima lettura per varianti con `/`, ü/toni neutri/erhua/sandhi contestuale espliciti. Manifest con letture, fonemi, hash, durata e RMS per ID; non dichiarare revisione umana o naturalezza universale di tutte le voci.
- Il generatore richiede Python 3.12, uv e FFmpeg/libmp3lame; `.venv-audio/` e pesi esclusi da git/build. Nessuna dipendenza TTS sul client: solo MP3. `Word` non contiene più il duplicato legacy `speech`; gli ID e IndexedDB restano invariati.
- Grammatica: 572 punti dell’Appendice A GF0025-2021, nuovi per blocco 48/81/81/76/71/67/148; 1.365 esempi con pinyin esplicito, spiegazioni e traduzioni italiane originali. `grammar-index.json` conserva inventario e metadati; `grammar-level-{1..7}.json` contiene le lezioni. ID `G1-001` ecc. locali, non numeri ufficiali dell’Appendice; `sourceNo` conserva il CSV originale e l’ordine avanzato differisce dal PDF. Provenienza/SHA e correzioni in `public/data/README.md`: escludere il rinvio non numerato No123, reintegrare 一定 in No67, correggere la funzione preposizionale di 将 in No297.
- `src/grammar.ts`: sezione solo del livello selezionato, cache Promise con espulsione degli errori, `loadRules` condiviso con i test. `details/summary` nativi e corpi lazy. Nessun autoplay/precaricamento all’apertura; Ascolta usa `public/audio/grammar/{ID-esempio}.mp3` con lo stesso player delle flashcard. Stop alla chiusura/cambio sezione; errori per esempio con recupero esplicito.
- `scripts/generate-grammar-audio.py`: riusa il generatore del vocabolario senza modificarne hash o corpus; frasi intere con pause e confini del sandhi. Pinyin editoriale esplicito, non sostituzione automatica dei polifonici; correzione di 一 per numerali/ordinali/decimali/finali di parola e tono sottostante dei classificatori neutri, senza cambiare la sillaba neutra. Rifiutare disallineamento, fonemi ignoti e oltre 510 token, mai troncare. Manifest indipendente con fonti/letture/fonemi/hash; generazione riprendibile CPU a due worker. Nessuna dipendenza aggiunta al client né revisione d’ascolto umana dichiarata.
- Progressione: `curriculum-level-{1..7}.json` contiene permutazioni complete degli ID di parole/regole del proprio blocco. Con N parole e R regole, la regola i usa il prefisso `floor(N*i/R)` e tutti i livelli precedenti; HSK1 ha 48 regole, non 50. L’ordine riguarda l’introduzione delle nuove: non riscrivere carte/storico/scadenze, non alterare la precedenza FSRS dei ripassi. I JSON ufficiali del vocabolario e i suoi MP3 restano invariati.
- `scripts/curriculum.py`: pianificazione/controllo offline stdlib, segmentazione lessicale con identità fonetiche distinte, controllo dei prefissi anche nei titoli/schemi/spiegazioni cinesi e negli esempi. `scripts/sources/grammar-forms.json` autorizza solo forme documentate dalla regola proprietaria; suffissi/prefissi vincolati, separazione di 洗澡, reduplicazioni AA/AABB/A一A su radici note, varianti intonative di 啊2 solo con l’ID L4-0002 e G4-022. Non trasformare parole ignote in caratteri liberi né unire polifonici per grafia. `--build` crea soltanto percorsi mancanti validi, senza riordinare quelli già fissati.
- `src/curriculum.ts`: cache Promise del percorso con espulsione degli errori, riordino tramite Map una volta al caricamento; scheduler O(n) invariato. `src/readings.ts`: Letture tra Grammatica e Test, cache del solo livello e protezione dalle risposte obsolete; `details/summary` e paragrafi alla prima apertura. Due checkbox indipendenti Pinyin/Traduzione, entrambi nascosti inizialmente; nessun audio.
- Letture: `readings-level-{1..7}.json`, ID R1-01 ecc., dieci testi per blocco (70 testi/193 paragrafi), temi vari. `paragraphs` contiene oggetti `{hanzi,pinyin,translation}`, non più stringhe. Cinese originario preservato. Lettura j: prefisso `floor(N*j/10)` e relative regole disponibili, più livelli precedenti. `grammarIds` comprende costrutti mirati e proprietari delle forme legate, non un albero sintattico esaustivo. Validazione lessicale/Pinyin e revisione editoriale separate, nessuna revisione madrelingua umana dichiarata.
- Validatore: stato DP conserva le ultime identità necessarie per reduplicazione/forme legate, evitando di scartare la segmentazione valida in 好好看看. Toni neutri contestuali senza voce neutra propria mantengono tutte le identità di citazione irrisolte e richiedono che siano già disponibili; la reduplicazione eredita invece l’identità della radice. Non confondere 地 de con dì né 看 kàn con kān.
- `src/quiz.ts`: pool cumulativi completi, 5 domande per tipo (hanzi→Pinyin, hanzi→italiano, frase→italiano, italiano→hanzi), quattro opzioni, 15 ID parola e 5 regole distinti. Campionamento Floyd di piccoli sottoinsiemi, nessuna copia/shuffle dell’intero mazzo per tentativo; scelte filtrate per letture valide e sovrapposizioni conservative di significato/contenuto, non parser semantico completo. `test-pinyin.json` deriva le letture delle 138 grafie duplicate globali, anche future: nessuna lettura valida offerta come errore.
- `src/tests.ts`: fetch solo entrando in Test, cache Promise con espulsione degli errori, richieste obsolete ignorate. Radio native e Avanti/Termina; prima risposta errata confermata salva immediatamente l’azzeramento, un perfetto si salva solo dopo tutte le 20 risposte. Incompleti non assegnano successi. Blocco dei doppi invii e recupero della stessa risposta dopo errore transazionale; hide/show sullo stesso livello conserva il tentativo. Nessun audio, timer o storico; livello successivo disponibile dal selettore dopo 20 perfetti, nessun livello 8 separato dopo il blocco 7–9.
- Contratti TypeScript nominati al modulo proprietario; preferire Promise.withResolvers; Map per progressi dinamici, Record per lookup statici.

## Comandi e verifica svolta

Node >=24. `npm ci`, `npm run dev`, `npm run build`, `npm run preview`, `npm test`, `npm run data:import`. Solo per sviluppo audio, dopo setup documentato nel README: `npm run audio:generate`, `npm run audio:check`, `npm run audio:test`.

Grammatica: `npm run grammar:check`; nello stesso ambiente audio fissato: `npm run grammar:audio`, `npm run grammar:audio:check`, `npm run grammar:audio:test`. `python3 scripts/check-grammar.py --write-index` rigenera soltanto l’inventario canonico dal CSV vendorizzato, non le lezioni editoriali.
